Executive summary, v2

The blockers are fixed, but nothing has shipped yet

Since v1, the two biggest blockers have been fixed, but neither fix has reached search engines yet.

  • AI crawlers are allowed in. Cloudflare's managed robots.txt and AI-bot blocking are off. GPTBot, ClaudeBot, Google-Extended, CCBot and PerplexityBot now get HTTP 200. HTTP now redirects to HTTPS, HSTS and nosniff are on, and Cloudflare Web Analytics is loading.
  • The branch serves real HTML. On feat/seo-geo the homepage ships about 44,000 characters of text, 13 headings at h1/h2 level, structured data, a FAQ and 32 internal links before any JavaScript runs.
  • None of the branch work is live. The branch is not committed or deployed. The live site still serves the 2.2 KB empty shell, so the AI crawlers that are now allowed in still find nothing to read.

The review also found two problems that v1 missed. The animated skills cloud keeps the browser busy about 90% of the time on mobile, giving a Total Blocking Time of about 2 minutes on both versions (N-01). And in the branch, React throws away the prerendered page 0.65 seconds after load and rebuilds it, so Googlebot indexes 21 of 86 projects (N-02).

Changes made during this review

Applied to feat/seo-geo and included in the measurements.

  • Prerender robustness. The step caches the original SPA shell, so it can be re-run on an already built folder, and no longer injects the same head tag twice. The privacy page no longer inherits the homepage head and shrank from 38 KB to 23 KB.
  • Accessibility. Carousel previous, next and slide-dot buttons, the map and grid toggles, and the company website and LinkedIn icon links now have accessible names. Links inside data-driven descriptions get rel="noopener noreferrer". Lighthouse accessibility went from 92 to 97.
  • .cache/ is ignored by git.

A. Skills cloud loop that only runs when it should

Applied to the existing effect in src/components/ui/item-cloud.tsx. Drop var(--cloud-depth) from the item's inline opacity once the loop writes opacity directly.

B. Hydration outline

Two rules keep the first client render identical to the prerender: lists render every item and hide extras with hidden="until-found" instead of slicing, and counters and reveal blocks start in their final state when hydrating.

C. robots.txt for the CV folder

Either delete the four unused PDFs, or keep only the two linked versions crawlable. Google and Bing apply the most specific rule, so the two Allow lines win. Update them whenever src/data/cv.json points to a new version.
